# Угощения — Match-3

Существующая игра с полем 4×4, белым фоном, тонкой зелёной пунктирной сеткой и четырьмя оригинальными 3D-десертами. Начальная схема сохранена: `ADBA / CBAB / DCBC / CDAD`. На ней пять результативных ходов и нет готовых троек.

## Запуск и сборка

Node.js 20.19+ или 22.12+ (среда разработки: Node.js 24).

```sh
npm ci
npm run dev -- --strictPort
npm run build
```

Vite слушает `0.0.0.0:5173`. Production-сайт находится в `dist/`; он работает на обычном статическом HTTPS-хостинге без API, базы данных и секретов. Для просмотра сборки: `npm run preview -- --strictPort` (сначала остановите dev-сервер на том же порту).

## Открытие на iPhone

Открывайте **публичную HTTPS-ссылку сайта в Safari**, а не скачанный HTML через просмотрщик вложений iOS. Просмотрщик может не исполнять JavaScript. Прежняя версия создавала все десерты только скриптом, поэтому без JavaScript была видна одна сетка. Теперь все 16 `<picture>/<img>` присутствуют в production-HTML; при отключённых скриптах видны изображения и пояснение, почему нельзя играть.

Каждый десерт — отдельный WebP в `public/assets/`, с отдельным PNG-резервом. Нет Base64, CSS-атласа или внешнего CDN. Имена файлов содержат хеш содержимого; масштаб и прозрачность извлечены из оригинала без перерисовки. Исходный атлас `assets/desserts.png` хранится только для воспроизводимости и не входит в production-сайт. Повторная подготовка файлов: `npm run assets:extract`.

## Управление

- Мышь: два последовательных клика по соседним элементам или перетаскивание.
- Сенсорный экран: два касания соседних клеток или свайп к соседу.
- Совпадения из трёх и более элементов по горизонтали/вертикали мягко подсвечиваются и исчезают. Элементы падают, новые появляются сверху, каскады обрабатываются автоматически.
- Нерезультативный ход возвращается назад. Если остаётся меньше двух возможных ходов, поле обновляется.
- Клавиатура: Tab/стрелки — фокус, Enter/Пробел — выбор, Escape — отмена.
- Перезагрузка восстанавливает исходную расстановку. Учитывается `prefers-reduced-motion`.

## Публикация

### Netlify: готовый архив

1. Соберите сайт: `npm ci && npm run build` (готовый архив релиза уже содержит эту сборку).
2. Войдите в Netlify и откройте https://app.netlify.com/drop.
3. Перетащите папку `dist` или ZIP, в корне которого находятся `index.html`, `assets/`, `_headers` и `favicon.svg`.
4. Откройте выданный адрес `https://…netlify.app/` в Safari. Он публичный и не требует установки приложения.

Для автоматических обновлений подключите Git-репозиторий в Netlify. `netlify.toml` задаёт сборку и каталог публикации.

### Vercel

Импортируйте репозиторий в Vercel, выберите Node.js 24 и нажмите Deploy. `vercel.json` задаёт сборку, каталог `dist` и заголовки. Если изменения ещё не отправлены в GitHub, сначала отправьте исходники в выбранный репозиторий. Переменные окружения для самой игры не требуются.

### Кэш и CSP

HTML проверяется заново (`Cache-Control: public, max-age=0, must-revalidate`), изображения и JS/CSS имеют имена с хешами и кэшируются как immutable. Service Worker не используется. Обновления сайта не зависят от старого HTML-вложения на телефоне. CSP разрешает скрипты и изображения только с текущего сайта; inline JavaScript не нужен. Inline CSS разрешён для позиции и анимации элементов. CSP также встроена в production-HTML для хостингов без пользовательских заголовков.

Доступ GitHub-интеграции к репозиторию не означает доступ к Pages: при этой подготовке создание Pages вернуло HTTP 403 `Resource not accessible by integration`. Публичный сайт автоматически не опубликован.

## Проверки

```sh
npm test
npm run build
npx playwright install --with-deps webkit chromium
npm run test:production
```

`test:production` обслуживает **собранную папку dist**, без Vite. Проверяет WebKit и Chromium на 375×812, 390×844, 430×932, 768×1024 и 1440×1000, а также смену ориентации. Проверяются реальные цветные пиксели в каждой из 16 клеток, декодирование изображений, PNG-резерв, касания, подсветка/исчезновение/заполнение, отсутствие ошибок JS/CSP/HTTP. Настоящий touch-swipe проверяется через Chromium Input; в WebKit проверяются нативные касания и pointer drag. Это проверка движков на Linux, а не физических iPhone.

После публикации запустите **тот же тест против публичного HTTPS-адреса**:

```sh
TEST_URL=https://YOUR-SITE.netlify.app/ npm run test:production
```

Для уже установленного браузера можно задать `CHROMIUM_PATH` или `WEBKIT_EXECUTABLE_PATH`. В текущей облачной среде WebKit запускается через `WEBKIT_EXECUTABLE_PATH=/workspace/.webkit-deps/run-webkit`: локальный launcher использует недостающие библиотеки из проверенного Debian-репозитория. Это не часть приложения и не требуется при публикации.

`npm run test:browser` — дополнительные проверки клавиатуры, возврата неудачного хода, reduced-motion и 12 последовательных ходов на работающем dev-сервере. Скриншоты сохраняются в `test-results/`.
